# Deployment foundation

Commercial deployment is not authorized. LEGAL_COMMERCIAL_GATE_APPROVED defaults to false and setting true is rejected. There is no payment provider, checkout, card collection, or billing webhook.

For an explicitly authorized staging deployment, provision PostgreSQL 18 with encrypted storage/backups and verified TLS, a separate migration owner and non-owner runtime login, authenticated SMTPS mail, TLS reverse proxy, and a secret manager. Apply migrations with migration credentials; use `database/runtime-grants.sql` with the runtime login. Never run synthetic seeds in STAGING/PRODUCTION. Do not copy `.local` or `.env` into artifacts. Include upstream dependency notices and resolve any binary redistribution obligations described in docs/DEPENDENCY_LICENSING.md.

Build with `npm ci` and `npm run build`. Inject APP_ENV=STAGING/PRODUCTION, DATABASE_URL (sslmode=verify-full or verify-ca), AUTH_SECRET (random, >=32 characters), API_ORIGIN, WEB_ORIGIN, ADMIN_ORIGIN, PORT, MAIL_MODE=SMTP, SMTP_URL, MAIL_FROM, and LEGAL_COMMERCIAL_GATE_APPROVED=false. Run migrations before the application. Startup fails when required configuration is absent. API binds loopback: run a local reverse proxy on the same host. No container/network binding mode is silently assumed.

Serve web and admin on the same public hostname using reverse-proxy path routing to preserve host-only cookie isolation; origins contain no path. Admin has the fixed Next basePath `/admin`: forward `/admin` and `/admin/*` unchanged to its server, including its assets. Admin application must remain server-rendered and call the API for every request. The web account proxy performs its own origin check. Never rewrite untrusted Origin or accept client-supplied role headers. Configure a trustworthy proxy/IP rate-limiting design before multi-user deployment; current loopback proxy requests conservatively share one IP bucket. Health is `/health`; account/admin responses are not publicly cached. Disable request body/query/header logging at proxies and process managers, and disable Next/Expo telemetry in build/CI.

Run `node --env-file=.env dist/api/start.js`, `npm run start:web`, and `npm run start:admin` for a local production-mode check. In deployed environments inject secrets directly instead of copying local env. Use explicit Node Next commands with injected origins for Next services. Schedule expired-auth maintenance daily with the deployment scheduler. Audit events are not erased by maintenance. Before launch, the owner must approve operational retention, administrative bootstrap and monitoring procedures; these are not invented by the foundation.

No mobile signing credentials, app-store submission, health entitlement, notification capability, or geolocation permission is configured. Credential-free Expo exports validate the shell. Production delivery, hosted CI, and device validation require the respective environments and are not inferred from local build success.
