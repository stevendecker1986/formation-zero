# Independent validation boundary

Phase D proposes a candidate session. Phase E checks the persisted artifact without importing Phase D construction code, timing helpers, schemas or selection algorithms. Its package depends only on Zod and Phase C's rule-engine interface. Phase E owns permissive inspection schemas, timing arithmetic, slot/section recomputation, demand aggregation, code semantics, fingerprints and contradiction checks.

The server supplies the exact encrypted construction input and current authoritative content evidence. Phase E invokes Phase C `evaluate` with the exact rules, facts, candidate and selected intensity; Phase D's saved `eligible`, constraint, total and rationale assertions are evidence to compare, never proof. Tests enforce the package dependency boundary and mutate builder output after construction.
